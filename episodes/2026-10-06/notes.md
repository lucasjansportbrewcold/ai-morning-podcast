## News
### 1. Claude Cowork moves the whole agent into a cloud sandbox, and today is the switch-over day
- Why it matters for Lucas: This is a real-world architecture choice on his top-priority question: where an autonomous agent should run, and what it can touch. Anthropic moved from "model in the cloud, tool VM on your laptop" to "model and VM in the cloud, one sandbox per session, the desktop app brokers local file access". That is the same split he would design for a pipeline that has to keep running without him.
- Facts:
  - Felix Rieseberg (Anthropic): the "old" Cowork ran inference in the cloud but executed tool calls in an Anthropic-provided VM shipped to the user's computer, added "for capability, safety, and security reasons", mapping in only the data explicitly added to a session [primary] (https://simonwillison.net/2026/Oct/5/felix-rieseberg/)
  - Reasons for the change, per Rieseberg: users disliked the disk, battery and performance cost of the local VM, and that closing the laptop stopped the work [primary] (https://simonwillison.net/2026/Oct/5/felix-rieseberg/)
  - New design: inference and the VM both run in the cloud; "Each session gets its own sandbox, not sharing state with other sessions"; when the VM needs something on the user's device, such as a file, the desktop app handles that file-access tool call [primary] (https://simonwillison.net/2026/Oct/5/felix-rieseberg/)
  - Help page: work continues in the background when the laptop is closed, and scheduled tasks run with no device online [primary] (https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile)
  - Local file access, browser use and computer use still need the desktop app to be open; when a task needs a file in the cloud, Claude fetches a copy of just that file; deleting a session deletes the fetched copies, per Anthropic's data retention practices [primary] (https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile)
  - Local connectors and plugins that include local MCP servers work only through the desktop app [primary] (https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile)
  - Pro and Max plans move to cloud-only tasks on October 6, 2026 (today); cloud sessions can be resumed from desktop, web, mobile and the Chrome side panel [primary] (https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile)
- Skeptic angle / open questions: The security boundary has moved, it hasn't disappeared. The desktop app is now a broker that serves files on request from a cloud agent, so the interesting questions are which folders it will serve, whether a prompt-injected session can ask for files outside the task, and how much a user sees of each fetch. Copies of local files now sit on Anthropic's servers for the life of the session. Running unattended (laptop closed, scheduled tasks) also removes the human who would otherwise notice something odd mid-run. Context from last week: OpenAI cancelled the GPT-6.1 Astra launch after tests showed it sometimes kept pursuing tasks without user permission ("scope authorisation") [secondary] (https://qz.com/openai-gpt-61-astra-canceled-safety-deception-092826). Agents that run longer with nobody watching make that failure mode matter more.
- Mia hook: "I had Cowork chewing through a folder of PDFs and shut the lid on the train, and before today that killed the job. Now it keeps going. But my first question was: what exactly does the desktop app hand over when the cloud VM asks for a file? Is it a per-folder allowlist, or whatever the agent requests?"

### 2. Reflection announces Beam, a 501B open-weight MoE, with weights promised for later this month
- Why it matters for Lucas: A US lab is promising a frontier-class, Apache 2.0, coding and agent model with only 23B active parameters. If the numbers hold, it's a serious candidate for self-hosted agent work where data can't leave the building, which matters for Dutch research and government use. Europe's answer this week, Aleph Alpha's Kolibri, sits at the other end: small active size, German-English, also Apache 2.0.
- Facts:
  - Beam: sparse mixture-of-experts, 501 billion total and 23 billion active parameters, built for coding, reasoning and agentic workloads; text-only input [primary] (https://reflection.ai/blog/introducing-beam)
  - Context: 256K tokens in pretraining, extended to 1M tokens during midtraining [primary] (https://reflection.ai/blog/introducing-beam)
  - Training: 23.8 trillion pretraining tokens; Reflection says about 95% of raw internet tokens were eliminated through parsing, deduplication and curation. Pretraining on 6,144 NVIDIA GB300 GPUs in under four weeks; RL on 10.5K GB300 GPUs for four weeks, about 1 million coding, agentic and STEM environments, over 100 million rollouts [primary] (https://reflection.ai/blog/introducing-beam)
  - Reported scores: SWE-bench Verified 80.9, SWE Bench Pro v2-Hard 77.2, Terminal Bench v2.1 80.1, MCP Atlas 78.7, GPQA Diamond 90.5, AIME 2026 97.8 [primary] (https://reflection.ai/blog/introducing-beam)
  - Reflection describes Beam as "approaching Qwen 3.8-Max on coding and agentic tasks" and claims 3–4× less inference compute than GLM-5.2 on reasoning benchmarks; its compute accounting excludes prompt prefill, context-dependent attention operations and serving overhead [primary] (https://reflection.ai/blog/introducing-beam)
  - License Apache 2.0. Weights, technical report and developer artifacts are planned for "later this month"; the model is still "undergoing final red-teaming and evaluations"; early access is through a waitlist. No pricing given [primary] (https://reflection.ai/blog/introducing-beam)
  - Aleph Alpha's Kolibri: German-English MoE, 78B parameters with about 3B active per token, over 21% German training data, trained on 768 B200 GPUs in Germany and Finland, Apache 2.0 weights [secondary] (https://the-decoder.com/aleph-alpha-releases-kolibri-an-open-weight-model-that-makes-the-case-for-european-ai-sovereignty/)
- Skeptic angle / open questions: Beam is an announcement, not a release. Every number is self-reported and the weights aren't out, so independent evals and quantised local runs have to wait. The efficiency claim leaves out prefill and attention costs, which dominate in long-context agent sessions. 501B total parameters still means multi-GPU serving even at 23B active. Watch for the technical report, the actual licence text on the weights, and whether third-party SWE-bench runs reproduce 80.9.
- Mia hook: "23B active sounds cheap, but you still have to hold 501B parameters in memory. What does it cost to actually host this for a team of ten researchers, compared with paying for Qwen 3.8-Max through an API?"

### 3. OpenAI turns on EU text watermarking, but lets API customers worldwide opt out
- Why it matters for Lucas: AI Act Article 50 text marking is now changing what each provider ships. Anthropic watermarks all Claude output worldwide; OpenAI watermarks EU ChatGPT and makes it optional for the API. If he builds text pipelines for Dutch clients, or uses detectors to measure AI text in research data, which provider generated the text decides whether a mark exists at all.
- Facts:
  - The EU AI Act's Article 50 transparency obligations, which require generated text, audio, image and video to be "marked in a machine-readable format", became enforceable on August 2, 2026 [secondary] (https://infoq.com/news/2026/08/eu-ai-content-watermark)
  - OpenAI will apply its "textGrain" watermark to ChatGPT and Codex users in the EU over the coming weeks; for API customers worldwide, including cloud partners such as Microsoft Azure, it is optional [secondary] (https://the-decoder.com/openai-will-watermark-chatgpt-text-in-the-eu-but-makes-it-optional-for-api-users-worldwide/)
  - textGrain embeds a statistical signal in word choices. At a 1% false-positive target: about 95% detection on 400-token psychology passages and about 80% on 200-token passages, substantially lower on math. Replacing 10% of words drops 400-token detection from 92% to 66%; replacing 25% drops it below 20% [secondary] (https://the-decoder.com/openai-will-watermark-chatgpt-text-in-the-eu-but-makes-it-optional-for-api-users-worldwide/)
  - Detector access starts with researchers and specialist organisations, approved case by case. OpenAI reports no significant benchmark differences with the watermark on versus off, and plans to open-source textGrain [secondary] (https://the-decoder.com/openai-will-watermark-chatgpt-text-in-the-eu-but-makes-it-optional-for-api-users-worldwide/)
  - Anthropic began marking Claude output on August 2, 2026, worldwide, saying it "does not yet have a durable way to scope it by region". Its scheme marks "what Claude touched, not what Claude wrote", so translations or summaries of user text are marked too; it is weak on short passages, factual text and code [secondary] (https://thenextweb.com/news/claude-watermark-eu-ai-act-exemptions-detection-api)
  - The sources disagree on Anthropic's detector. In August, TNW reported a commitment to "a free detection API so anyone can check"; The Decoder now describes Anthropic's detection access as restricted, like OpenAI's [secondary] (https://thenextweb.com/news/claude-watermark-eu-ai-act-exemptions-detection-api) (https://the-decoder.com/openai-will-watermark-chatgpt-text-in-the-eu-but-makes-it-optional-for-api-users-worldwide/)
- Skeptic angle / open questions: A watermark that one paraphrase pass through another model removes is a compliance artefact, not a provenance guarantee. Optional marking on the API means that the bulk-generated text the rule cares most about can go out unmarked. For researchers, the absence of a mark proves nothing, and detection is weakest on short and technical text, which is exactly what economists write. Watch the Commission's Code of Practice and whether regulators accept an opt-out API as compliant.
- Mia hook: "If I translate my own Dutch draft with Claude, my text now carries a watermark. Does that make my human-written paper 'AI-generated' to a journal's detector?"

### 4. Nearly 30% of 2026 US STEM dissertations contain AI writing, and those authors leave academia more often
- Why it matters for Lucas: Rare near-census evidence on AI diffusion inside research training itself, with a clean placebo period. It speaks directly to his field's question of whether offloading writing erodes the skill that writing is supposed to build.
- Facts:
  - NBER Working Paper 35859, Gross (Duke), Shvadron (Toronto), Zhang (Duke), October 2026 [primary] (https://www.nber.org/papers/w35859)
  - Sample: about 226,000 US STEM PhD graduates, 2019 to May 2026, from ProQuest plus university repositories; it matches the NSF Survey of Earned Doctorates closely, with about 85% coverage in engineering. Pangram 3.3.2 scored all abstracts plus a stratified random sample of 340 full texts [primary] (https://www.nber.org/system/files/working_papers/w35859/w35859.pdf)
  - Placebo: across roughly 126,000 dissertations from 2019–2022, Pangram flagged six abstracts, implying a false-positive rate below 0.01% [primary] (https://www.nber.org/system/files/working_papers/w35859/w35859.pdf)
  - Share with AI-generated abstracts: 1.7% (2023), 5.5% (2024), 18.8% (2025), 29.4% (2026, through May). Reweighted to full text: about 8% in 2024 and 31% in 2026, which the authors call lower bounds [primary] (https://www.nber.org/system/files/working_papers/w35859/w35859.pdf)
  - 2026 by field: 48% computer science, 51% civil engineering, 17% math and statistics. Non-English-speaking origin 41% vs 23% English-speaking. R1 28%, R2 31%, other doctoral institutions 37%. Top-10 programs 15% vs 26% for programs ranked 90–100 (2025–26). MIT 9%, Caltech 10%, Princeton 13% [primary] (https://www.nber.org/system/files/working_papers/w35859/w35859.pdf)
  - Careers: among US-origin R1 graduates of 2023–2025, comparing within university-field with year fixed effects, AI writing goes with 7.4 p.p. lower academic employment (base 44%) and 8.0 p.p. higher industry employment (base 50%). The effect attenuates substantially for foreign-origin graduates [primary] (https://www.nber.org/system/files/working_papers/w35859/w35859.pdf)
  - The authors call this correlational and name reverse causality (students heading to industry write lower-effort dissertations). Dissertation length does not correlate with AI use, and the gaps persist when controlling for length. They project a majority of US STEM dissertations will contain AI content by 2028 at current growth [primary] (https://www.nber.org/system/files/working_papers/w35859/w35859.pdf)
  - The authors disclose that Claude Fable 5.1 was used in the initial drafting of the discussion of findings and part of the data appendix, which they then substantially revised by hand [primary] (https://www.nber.org/system/files/working_papers/w35859/w35859.pdf)
- Skeptic angle / open questions: Measurement rests on one commercial detector applied to abstracts. The full-text validation is only 340 dissertations, and an AI abstract raises the probability of AI in the full text by 55 p.p., which is far from a one-to-one link. "AI writing" lumps polishing in with ghost-writing. The career result is a selection story until someone finds an instrument, and LinkedIn is an imperfect outcome measure. What it can't show yet: whether these graduates actually do worse research, judged by publications or grants. The detector-on-abstracts design is also exactly what watermarking (item 3) could replace or confuse.
- Mia hook: "I use Claude to fix my English in every paper intro. By this paper's measure, am I an 'AI-writing' researcher? Where should the line sit between polishing and offloading?"

## Deep dive: Right order, wrong scale: how to validate an LLM judge for the number you actually report
- Why this topic, why now: Lucas uses LLM graders everywhere: RAG answer quality, agent evals, and potentially silicon samples and task-exposure studies in his own research. A new MIT paper (Lyu and Thompson, arXiv 2610.02492, October 2026) audits 33 judge setups against 45,796 worker ratings and shows that the usual way of picking a judge, by agreement on rankings, says almost nothing about whether the judge gets acceptance rates or aggregates right. Those are the numbers that end up in headlines and in the economics of AI. It builds on, but differs from, recent deep dives: this one is about measurement validity of evals, not prompt injection, replication or harness overfitting.
- Outline:
  1. **Three kinds of validity.** Ordinal (does the judge prefer the same response?), cardinal (does it put scores at the same level and spread?) and aggregate (do task and occupation means agree?). Mechanism: within-task order is invariant to any shift and stretch of the scale (x' = a·x + b with a > 0), so a perfect ranker can still put every task mean anywhere. Paralegal example from the paper: the worker rates five summaries 5–9 with "acceptable" at 7 or higher, so three are acceptable; the judge rates them 1–5, ranks them perfectly, and calls none acceptable. Bradley–Terry-style pairwise scaling has the same blind spot: it identifies utilities only up to location and scale.
  2. **The audit design.** Ratings come from an existing survey (Mertens et al. 2026): US Prolific workers with self-reported occupational experience rating AI responses to O*NET tasks on a nine-point "manager_accept" scale, where 7 or higher counts as acceptable. Task- and worker-disjoint splits (36,649 / 4,646 / 4,501 ratings). 33 judge configurations across Claude Haiku 4.5 and Opus 4.7, GPT-5.4-mini, GPT-OSS-120B, DeepSeek-V4-Pro, Llama-3.3-70B and Qwen3.5-9B, including LoRA fine-tunes, few-shot, listwise, rubrics, self-consistency and ensembles, plus six dumb train-fitted controls.
  3. **Rankings are fine, levels are all over the place.** Every judge beats chance on ordering, with a median tie-aware pair accuracy of 0.631 and a best of 0.658. But a TF-IDF ridge regression on response text alone gets 0.643. All 33 mean-bias intervals exclude zero, with a median of −1.18 points. Opus 4.7 is the harshest at −3.23 and judges 3.0% of responses acceptable, against 61.1% for workers. Near-constant Llama calls 97.9% acceptable. Mechanism for why "zero mean bias" isn't enough: GPT-OSS has a bias of only +0.12, but a compressed distribution (SD ratio 0.83) piles mass near the threshold, giving 78.4% acceptable, a 17.3-point error.
  4. **Better ranking can make aggregates worse.** In one fine-tuned lineage, switching from pointwise to a few-shot/listwise bundle raised pair accuracy from 0.596 to 0.658, but cut correlation with worker means from 0.215 to 0.096 at task level and from 0.254 to 0.087 at occupation level. This replicated on the validation split under pre-specified criteria. Mechanism: listwise scoring becomes a within-set rank code. Only 18.1% of its variance lies between task instances, and its own within-set rank explains 90.1% of the rest. It loses the between-task location that aggregates need, and the share of variance tied to which model generated the response rises from 13.2% to 34.6%.
  5. **Repairs and their limits.** (a) Calibration: five-fold task-grouped isotonic calibration drives mean bias to ≤0.003, but the best cross-validated R² against individual worker ratings is 0.085. Calibrating to the mean and then thresholding still leaves a median acceptance-share error of 10.7 points. Calibrating acceptance probabilities directly brings pooled error to ≤0.1 point, but so does a fold-fitted constant with no judge at all. Match the calibration target to the estimand. (b) Prediction-powered inference (Angelopoulos et al. 2023) uses judge predictions on unlabeled data plus a human-labeled sample that corrects their bias, with valid confidence intervals and no assumptions about the model. Its efficiency gain depends on how predictive the judge is: with R² ≤ 0.085, the best linear correction can cut estimator SD by at most about 4.3%, and the paper found SD ratios of 0.96–1.02. Related theory (Dorner, Nastl and Hardt, ICLR 2025): a judge no more accurate than the evaluated model cannot cut annotation needs by more than half.
  6. **Choose the judge for the quantity you report.** In a selection experiment over 1,000 random half-splits, picking the judge by pair accuracy gave a mean acceptance-share error of 10.5 points, while picking it directly on acceptance-share error gave 5.8 points, at a cost of only 0.018 in pair accuracy. The paper's six-item reporting standard: (1) name the decision level before choosing the judge; (2) report tie-aware accuracy plus coverage, and randomise order in listwise prompts; (3) report signed bias, SD ratio, the full distribution and a threshold sweep; (4) include simple lexical and group-mean controls; (5) use clustered, level-matched uncertainty and report the reliability of the human target; (6) confirm the chosen configuration on held-out data under pre-specified criteria.
- Facts and examples with sources:
  - Authors Harry Lyu and Neil Thompson (MIT); O*NET-BENCH built from 45,796 worker ratings; 33 configurations across six model families; 4,501 test ratings [primary] (https://arxiv.org/abs/2610.02492)
  - 25 configurations reach tie-aware pair accuracy ≥0.60; median 0.631; best near-complete 0.658 (fine-tuned few-shot/listwise, coverage 0.912); response-only TF-IDF control 0.643 at full coverage [primary] (https://arxiv.org/pdf/2610.02492)
  - Coverage trap: Llama-3.3-70B orders only 5.1% of worker-decisive pairs, so its conditional accuracy of 0.631 becomes a tie-aware accuracy of 0.507 [primary] (https://arxiv.org/pdf/2610.02492)
  - Mean bias: 29 configurations below workers, 4 above; median −1.18; Opus 4.7 −3.23 [−3.36, −3.11], equal to 1.7 worker SDs, and lower than the worker on 86% of responses; GPT-OSS-120B pointwise +0.12 [0.01, 0.22] [primary] (https://arxiv.org/pdf/2610.02492)
  - Acceptance shares: workers 61.1%; judges 3.0% (Opus) to 97.9% (Llama), median 43.9%; pointwise fine-tunes 89.8% and 90.8%; TF-IDF control 43.5% despite a bias of only −0.05 [primary] (https://arxiv.org/pdf/2610.02492)
  - Occupation classification: workers say a majority of responses is acceptable in 68.7% of 307 occupations; Opus in 0.3%, disagreeing with the worker majority in 68.4% of occupations; GPT-OSS and the pointwise fine-tune disagree in 30.9% and 31.3%, about the same as a constant "everything acceptable" classifier (31.3%) [primary] (https://arxiv.org/pdf/2610.02492)
  - Ordering vs placement across 32 near-complete configurations: Pearson −0.22 between pair accuracy and signed bias. Opus and the pointwise fine-tune sit 4.4 points apart in mean bias at nearly identical pair accuracy (0.595 vs 0.596) [primary] (https://arxiv.org/pdf/2610.02492)
  - Limitations stated by the authors: one worker rating per response, low occupation-level split-half reliability (Spearman–Brown 0.093), English text and US occupations only, a sample that isn't employment-weighted, test-split analyses that are exploratory, and listwise order that wasn't randomised [primary] (https://arxiv.org/pdf/2610.02492)
  - Prediction-powered inference gives "provably valid confidence intervals" for means, quantiles and regression coefficients "without making any assumptions on the machine-learning algorithm"; more accurate predictions give smaller intervals [primary] (https://arxiv.org/abs/2301.09633)
- Practical takeaway Lucas could apply this week: Pick one LLM judge he already uses, such as the grader for a RAG app or a check on these podcast notes. Hand-label about 150 items on the same scale and write down the decision he actually makes from it ("share acceptable", "pass/fail per document"). Then compute four things: tie-aware pair accuracy with coverage, signed mean bias, the SD ratio, and the acceptance-share gap over a threshold sweep. Add two dumb baselines: always predict the label mean, and a TF-IDF ridge regression. If the judge is a good ranker but misplaces the level, either use it only for ranking (top-k selection, reranking) or fit an isotonic calibration aimed directly at P(acceptable) on a grouped split. When reporting a headline rate, use PPI with the human labels so the confidence interval stays honest. The same check applies to silicon-sample work: an LLM that ranks survey options in the right order can still get the levels wrong.

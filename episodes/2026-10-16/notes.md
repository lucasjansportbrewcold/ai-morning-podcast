## News
### 1. TheoPhysEval: when the agent is right and the answer key is wrong
- Why it matters for Lucas: This is the clearest case yet of the problem behind validating AI-produced research. An AI agent's disagreement with the reference answer turned out to be a test of the experts. Anyone who builds evals or replication checks for economics output needs a procedure for the case where the "ground truth" is wrong.
- Facts:
  - TheoPhysEval is a suite of 50 unpublished, research-level theoretical physics problems with verifiable answers. A world expert could solve a typical problem in about a day or less. Experts in adjacent specialties would take considerably longer. [primary] (https://arxiv.org/html/2610.16733v1)
  - Problems come from 11 domains. Contributors adapted calculations from their own work by changing parameters, so the problems are new but can be solved with existing techniques. The authors compare them to training exercises for graduate students. [primary] (https://arxiv.org/html/2610.16733v1)
  - There are two tracks. "Realistic" allows web/literature search and local computation. "Isolated" allows only local computation, with no internet access. [primary] (https://arxiv.org/html/2610.16733v1)
  - Realistic track: GPT-6-Astra in Codex scored 49/50 (98%), Claude Opus 5.5 in Claude Code 46/50 (92%), Gemini 3.8 Flash 34/50, DeepSeek-V4.1-Flash 27/50 and GLM 5.3 21/50. Isolated track: Astra 46/50 and Opus 46/50. [primary] (https://arxiv.org/html/2610.16733v1)
  - The abstract says the average cost is under USD 3 per problem for the best agent. The Decoder's headline gives $2.40. [primary] (https://arxiv.org/html/2610.16733v1); [secondary] (https://the-decoder.com/gpt-6-astra-solves-49-of-50-physics-research-problems-at-2-40-apiece/)
  - Co-author Suvrat Raju: in the first evaluation, Astra scored "in the late eighties", with Opus 5.5 close behind. The models, Astra especially, insisted the expert answers were wrong. In multiple cases the experts then found subtle errors deep in their own calculations, and Astra's score rose to 49/50 as the answers were revised. [secondary, quoted via Marginal Revolution] (https://marginalrevolution.com/marginalrevolution/2026/10/astra-held-its-ground-truth.html)
  - The authors read the small gap between the two tracks as a sign that agents "have memorized large parts of the physics research literature". They say they cannot rule out data leakage, and some experts used AI while solving their own problems. [primary] (https://arxiv.org/html/2610.16733v1)
  - On "taste": when asked to come up with new problems, agents "focus excessively on details that a human might find uninteresting". The authors write that it is no longer appropriate to give such problems to starting researchers unless the point is to work through them rather than to get the answer. [primary] (https://arxiv.org/html/2610.16733v1)
  - Each agent was run once, and the problems are "turn-the-crank" calculations, not new theory. [primary] (https://arxiv.org/html/2610.16733v1)
- Skeptic angle / open questions: The reference answers were revised after the models disagreed, so the 98% partly depends on a process that the model being tested itself triggered. Did the authors also recheck cases where the model agreed with an expert answer that was wrong? Fifty problems and one run each give wide error bars, and the 92% vs 98% gap is three problems. A related benchmark of truly open problems (OpenProblemBench, 82 problems) puts Astra's judged solve rate at 14.0% (https://arxiv.org/abs/2610.11118) [primary]. Turning the crank is close to solved, but choosing which problem to work on is not.
- Mia hook: "I had my agent check a regression table from a paper, it flagged a mismatch, and I assumed the agent was wrong. How do you set up adjudication so the default isn't 'the human is right'? Do you need a third, blind solver?"

### 2. GitHub Copilot is getting local models, and agent commands run in an OS sandbox
- Why it matters for Lucas: A mainstream coding agent now ships with deny-by-default OS sandboxing and can run a capable local model behind it. That is close to the setup he wants for autonomous work on sensitive data: the model stays local and the commands are boxed in.
- Facts:
  - GitHub Copilot will get local model capabilities by the end of October 2026. Tasks are routed between on-device and cloud inference automatically, or developers can pick local models explicitly. Copilot supports the Windows ML provider and OpenAI-compatible endpoints. It rolls out across Copilot CLI, the Copilot app and VS Code. [primary] (https://commandline.microsoft.com/local-models-sandboxed-tools-github-windows/)
  - The local MAI Code 1.1 Flash is a MoE with 137B total and 6.8B active parameters. Quantization makes it about 80% smaller than the cloud BF16 version, roughly 53GB. It scores 70.80% on SWE-Bench Verified and 66.29% on Terminal-Bench 2.1. On a Surface Laptop Ultra, prompt processing runs at 923.5 tok/s at 64k context and 769.8 tok/s at 128k. [primary] (https://commandline.microsoft.com/local-models-sandboxed-tools-github-windows/)
  - Copilot sandboxes agent commands with Microsoft Execution Containers (MXC), "an open-source library from the Windows team that translates policy into native operating-system controls". On Windows it uses the BaseContainer tier of the ProcessContainer backend to restrict files, network, credentials, system capabilities and execution paths. [primary] (https://commandline.microsoft.com/local-models-sandboxed-tools-github-windows/)
  - Default policy: the current working directory is read/write, and the rest of the system is "largely read-only or inaccessible". Sandbox settings can be configured per project. [primary] (https://commandline.microsoft.com/local-models-sandboxed-tools-github-windows/)
  - MXC is written in Rust and hosted on GitHub. Policies are JSON and deny by default, and TypeScript SDKs handle sandbox lifecycle. Version 0.8.0 was the latest as of 3 September 2026. The project says it cannot provide more isolation than a locked-down virtual environment, and it cannot switch virtualization backends on the fly. [secondary] (https://www.infoworld.com/article/4215416/running-ai-agents-in-sandboxes-with-microsoft-execution-containers.html)
- Skeptic angle / open questions: "Largely read-only" still means the agent can read a lot. Exfiltration risk depends on what is readable plus outbound network access, not only on what is writable. MXC is pre-1.0. Benchmark scores for the quantized local model come from Microsoft. Watch whether Copilot shows the sandbox policy in force, and whether network egress is allowlisted or just "outbound allowed".
- Mia hook: "I turned on a sandbox and my agent immediately needed my SSH key and a package registry. Where do you draw the line between a sandbox that is safe and one that is usable without punching ten holes in it?"

### 3. Meta releases Muse Spark Open: 816B open weights, built for agents, with a licence catch
- Why it matters for Lucas: This is the largest US open-weight model so far, built for long-horizon agentic work with 1M context and audio and video input. It runs (heavily quantized) on two Mac Studios. The licence and the hardware cost decide whether it is useful for anything he would build.
- Facts:
  - 816B total and 42B active parameters, 1M-token context. Input: text, image, video and audio. Output: text. Released 15 October 2026 for "coding and agentic work". [primary] (https://research.meta.ai/blog/muse-spark-open)
  - Architecture: 62 layers, 256 experts per MoE layer with 8 routed per token, and experts hold about 97% of the parameters. It uses grouped-query attention (128 query heads, 16 KV heads), at about 250 KB of KV cache per token in BF16. [primary] (https://huggingface.co/blog/meta-muse-spark-open)
  - The BF16 checkpoint is about 1.5 TB, and there is also an NVFP4 version. An MLX 3/4-bit quant on an M3 Ultra is 344 GB and runs at 225 tok/s prefill and 21 tok/s generation. A 2-bit llama.cpp quant runs at 18 tok/s on an M3 Ultra (512GB). [primary] (https://huggingface.co/blog/meta-muse-spark-open)
  - Meta says it is optimized to run on two Apple M5 Ultra Mac Studios. It is available on Hugging Face, SageMaker, Google Cloud and Microsoft Foundry, and hosted by Together, Fireworks, Baseten, Modal, Groq, Nebius and OpenRouter. It was evaluated under Meta's Superintelligence Scaling Framework with additional safety post-training. [primary] (https://research.meta.ai/blog/muse-spark-open)
  - Licence: the Muse Model License, with "limited commercial terms". According to The Decoder, you must label products "Built with Muse Spark Open", and API providers with more than $20 million a year in revenue need a separate agreement with Meta. [primary for licence name] (https://research.meta.ai/blog/muse-spark-open); [secondary for terms] (https://the-decoder.com/muse-spark-open-is-metas-answer-to-qwen-glm-and-kimi-in-the-open-weight-race/)
  - Meta claims it leads Qwen 3.8, GLM 5.3 and Kimi K3 on agentic, knowledge/reasoning and multimodal benchmarks, but falls behind some of them on coding. It is "well short" of Meta's paid Muse Wonder Full. [secondary] (https://the-decoder.com/muse-spark-open-is-metas-answer-to-qwen-glm-and-kimi-in-the-open-weight-race/)
  - The Hugging Face LoRA fine-tuning recipe freezes all experts and adapts only the attention projections. 500 steps on 64 H100s (about 2 hours) raised token accuracy from 72% to 84%. [primary] (https://huggingface.co/blog/meta-muse-spark-open)
- Skeptic angle / open questions: All benchmark claims come from Meta, and its own launch post leads with specs, not scores. Independent agentic evals will matter more. "Runs on Mac Studios" means 3-4 bit quantization at about 20 tok/s, which is fine for chat but slow for an agent loop that generates thousands of tokens per step. The labelling requirement and the custom licence make it less clean than Apache-licensed Chinese alternatives. That matters for Dutch public-sector or client work.
- Mia hook: "Twenty tokens a second sounds fine until your agent does 40 tool calls with reasoning in between. What is the real wall-clock time for one task, and is a hosted provider in the EU the better deal?"

### 5. LLMs get contested economic causal effects wrong in one direction
- Why it matters for Lucas: If he uses LLMs to screen literature, code mechanisms or draft policy notes, this paper shows a systematic directional bias on exactly the questions where economists disagree. Averaged out, it would not show up in a normal accuracy check.
- Facts:
  - "Ideological Bias in LLMs' Economic Causal Reasoning" (Lee, Yun, Kim, Min, Park, Park, Kim). v3 is dated 14 October 2026 and the paper is accepted at COLM 2026. [primary] (https://arxiv.org/abs/2604.21334)
  - Starting from 10,490 causal triplets (treatment, outcome, empirically verified sign) from top economics and finance journals, the authors flag 1,056 (10.1%) as ideology-contested: cases where intervention-oriented and market-oriented views predict opposite signs. The flags come from a majority vote of four LLMs that did not see the empirical result. [primary] (https://arxiv.org/html/2604.21334v3)
  - Contested items are harder. Closed models score 60.8% on contested items vs 74.5% on non-contested ones, and open models 51.7% vs 63.8%. [primary] (https://arxiv.org/html/2604.21334v3)
  - In 17 of 20 models, accuracy is higher when the true sign matches the intervention-oriented view. For closed models it is 72.5% vs 64.1% (+8.5 pp), and for open models the gap is +14.2 pp. Errors lean intervention-oriented in 15 of 20 models. [primary] (https://arxiv.org/html/2604.21334v3)
  - One-shot examples do not remove the asymmetry. Five prompt variants all keep a 7.4-14.6 pp gap. The gap survives difficulty matching (+9.5 pp matched vs +10.5 pp unmatched). It is largest in healthcare (+20.2 pp) and welfare/redistribution (+14.7 pp), and close to zero in trade (+1.0 pp). [primary] (https://arxiv.org/html/2604.21334v3)
  - The benchmark's own ground truth leans intervention-oriented (57.7% vs 42.3%). Controlling for the empirical sign attenuates the effect by only 10.7%, and the authors conclude the bias has several sources. [primary] (https://arxiv.org/html/2604.21334v3)
- Skeptic angle / open questions: Other LLMs labelled which items count as "contested", so the classification itself may carry model bias. The "truth" is the published sign, and published signs carry publication bias. The model set includes the GPT-4o generation, so current frontier models may differ. The bias may partly reflect the literature's priors rather than ideology. Still, the practical lesson holds: report accuracy split by the direction of the expected answer, not just in aggregate.
- Mia hook: "I use Claude to pre-screen papers for 'does X raise Y'. Should I run a sign-flipped version of every question, asking for the opposite direction, to see whether it just follows my framing?"

## Deep dive: Shrinking models without breaking them. PTQ, QAT and quantization-aware distillation, and what they mean for running agents locally
- Why this topic, why now: In one day, several releases bet on aggressive low-bit models for local agents. Meta's 816B Muse Spark Open runs on Macs only at 2-4 bit. NVIDIA's Nemotron 3.5 Bolt is a 74B agent model squeezed to 2 bits to fit in 24GB. Microsoft's MAI Code 1.1 Flash local is about 80% smaller than its BF16 cloud version. NVIDIA also put out an FP4 "QAD" quant of Qwen3.8-Flash-Next. For Lucas, local models are what make autonomous agents on confidential data (client data, microdata, Dutch public-sector work under the AVG/GDPR) possible. Whether a quant keeps the agentic skills, not just benchmark averages, decides whether that works. Past deep dives covered security, evals and orchestration, but never model compression.
- Outline:
  1. **Why bits are the bottleneck for local agents.** Generating a token reads the active weights from memory, so decode speed is bounded by memory bandwidth divided by the bytes of active weights. Capacity, meanwhile, must hold *all* weights plus the KV cache. With MoE, total parameters set the memory you need and active parameters set the speed. Muse Spark Open: 816B total, 42B active, about 1.5 TB in BF16 and 344 GB at 3/4-bit on MLX (21 tok/s on an M3 Ultra). MAI Code 1.1 Flash (137B/6.8B active) is about 53 GB locally. Bolt (74B/9B active) targets 24 GB. The KV cache adds up too: Muse needs about 250 KB per token in BF16, so a 1M-token context alone is about 250 GB. That is why serving recipes cap context at 131K on smaller rigs.
  2. **The formats: what "4-bit" actually means.** NVFP4 stores each value as E2M1 (1 sign, 2 exponent and 1 mantissa bit, roughly -6 to +6). Every 16 values share an FP8 (E4M3) scale, and a per-tensor FP32 scale extends the range. Compared with MXFP4 (blocks of 32, power-of-two E8M0 scales), the smaller blocks and fractional scales track local value ranges better, so the error is lower. The cost is about 4.5 bits per value: a 3.5x reduction vs FP16 and 1.8x vs FP8. GGUF's IQ2-XXS, used for Bolt, is 2.0625 bits per element. Mixed precision is standard practice: Bolt keeps experts at 2-bit, Mamba layers at NVFP4 and embeddings/output at Q8_0. NVIDIA's QAD runs keep attention layers and their neighbours in BF16.
  3. **PTQ: free, and fine for big models.** Post-training quantization only calibrates scales on a small dataset, with no training. Very large models tolerate it. DeepSeek R1 (671B) goes from official FP8 to NVFP4 with GPQA-D moving from 69.7 to 69.2 and AIME24 unchanged at 80.0. Smaller post-trained reasoning models lose much more: Llama Nemotron Super V1 drops from 46.0 to 32.3 on AIME25 under NVFP4 PTQ. NVIDIA also notes that classic outlier tricks (rotations, smoothing) stop helping at NVFP4's 16-value blocks.
  4. **QAT: retraining in low precision, and how it breaks RL-trained models.** Quantization-aware training fine-tunes the model with quantized weights/activations in the forward pass, using the original task loss (next-token cross-entropy). Modern models are SFT plus RL plus merges, so you cannot replay the pipeline. People fall back on SFT data, and that pulls the model back toward its pre-RL behaviour. On RL-heavy models, NVFP4 QAT was *worse than doing nothing*. AceReason Nemotron 7B on AIME25: BF16 63.5, PTQ 58.7, QAT 46.1. The deeper diagnosis: QAT matched BF16 cross-entropy (0.408) but had a KL divergence of 0.311 from the original model. It reached the same loss but behaved like a different model, in effect an extra post-training stage.
  5. **QAD: distil the original model into its quantized self.** Quantization-aware distillation trains the quantized student to match the full-precision teacher's output distribution (KL divergence, temperature 1) instead of the labels. It keeps the teacher's behaviour, including what RL taught it, without replaying RL. Results: KL to BF16 of 0.004 vs QAT's 0.311. AceReason AIME25 at 62.0 vs BF16 63.5. Nemotron 3 Nano AA-LCR (long-context reasoning) at 34.3 vs BF16 35.9 and PTQ 31.3. It is cheap and forgiving. It needs about 0.3-6B tokens depending on the model. Training only on code data recovered maths almost as well (AIME25 62.0, the same as with full data). Model-generated data works. Keeping the wrong answers in beat using only correct ones on AIME24 (71.9 vs 70.5) and LiveCodeBench (52.6 vs 52.3), though not on AIME25 (61.3 vs 61.6). Even random tokens did not break the model. Using a *larger* teacher did worse than the original model as teacher. Learning-rate guidance is 1e-5 to 1e-6, at or below the original SFT rate for SFT-heavy models and higher for RL-heavy ones.
  6. **What survives and what doesn't: check the agent skills.** Benchmark averages hide uneven loss. In NVIDIA's W4A4 NVFP4 run on Qwen3.6-35B-A3B, most scores were unchanged, but instruction following (IFBench) fell from 60.0 to 57.9 under PTQ and recovered to 59.6 with QAD (500 iterations, about 735 GPU-hours). Instruction following, schema adherence and long-context retrieval are exactly what an agent loop leans on. One malformed tool call per 50 steps ends a long run. Bolt's card claims "little to no degradation in text accuracy" vs its BF16 parent, but it is also compressed, RL'd and distilled, so you cannot separate the effects of quantization. Rule of thumb: accept PTQ for very large models, prefer vendor QAD checkpoints for small and mid-size or RL-heavy models, and always rerun your own task-level eval.
- Facts and examples with sources:
  - NVFP4 format: E2M1 elements, 16-value blocks with E4M3 scales, per-tensor FP32 scale, about 4.5 bits per value, 3.5x smaller than FP16 and 1.8x smaller than FP8. On DeepSeek-R1-0528, FP8 to NVFP4 PTQ costs "1% or less" accuracy across seven benchmarks. [primary] (https://developer.nvidia.com/blog/introducing-nvfp4-for-efficient-and-accurate-low-precision-inference/)
  - QAD technical report (Xin et al., NVIDIA, arXiv 2601.20088 v3, 3 March 2026). Its tables are the source for: QAT vs QAD KL (0.311 vs 0.004) at equal cross-entropy; Llama Nemotron Super V1 AIME25 (BF16 46.0 / PTQ 32.3 / QAT 41.5 / QAD 45.6); AceReason AIME25 (63.5 / 58.7 / 46.1 / 62.0); Nemotron 3 Nano AA-LCR (35.9 / 31.3 / 24.8 / 34.3); the cross-domain and data-source ablations; the teacher-size result (9B teacher beats 12B); and DeepSeek R1 PTQ robustness (GPQA-D 69.7 to 69.2). [primary] (https://arxiv.org/pdf/2601.20088)
  - The QAD report says PTQ "often struggles with small models and sensitive tasks", and that common PTQ algorithms often fail to improve on baseline NVFP4 because the small block size neutralizes outlier mitigation. [primary] (https://arxiv.org/pdf/2601.20088)
  - NVIDIA Model Optimizer, W4A4 NVFP4 on Qwen3.6-35B-A3B: IFBench BF16 60.0, PTQ 57.9, QAD 59.6. MMMU-Pro 74.6 / 73.4 / 73.9. 500 QAD iterations at 32K sequence length on 128 GB200s took 5.7 hours, about 735 GPU-hours. [primary] (https://nvidia.github.io/Model-Optimizer/announcements/qwen36-w4a4-qad.html)
  - Nemotron 3.5 Bolt 74B-A9B-24GB: compressed from the 120B-A12B parent, then RL'd on MCP and SWE tasks, then QAD on the expert weights. Experts at IQ2-XXS (2.0625 bits), Mamba layers NVFP4, embeddings/output Q8_0. A 32GB recipe gives 262,144-token context with up to 7 speculative draft tokens. Licence OpenMDW-1.1. Claimed scores include Terminal-Bench 2.1 at 50.98 and MCP-Atlas at 52.20, against Qwen3.6-35B at 44.38 and 51.20. [primary] (https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-24GB-GGUF)
  - NVIDIA's FP4 QAD quant of Qwen3.8-Flash-Next is reported at 102GB vs 133GB for the NVFP4 version. [secondary] (https://www.reddit.com/r/LocalLLaMA/comments/1x6vqft/fp4_qad_quant_of_qwen38flashnext_from_nvidia/)
  - Muse Spark Open sizes and speeds (1.5 TB BF16; MLX 344 GB, 21 tok/s; KV about 250 KB/token BF16; 131K serving context on 8x RTX Pro 6000, 1M on 8x H200). [primary] (https://huggingface.co/blog/meta-muse-spark-open)
  - MAI Code 1.1 Flash local: 137B/6.8B active, about 53GB, about 80% smaller than cloud BF16, SWE-Bench Verified 70.80%. [primary] (https://commandline.microsoft.com/local-models-sandboxed-tools-github-windows/)
- Practical takeaway Lucas could apply this week: Pick one of his own agent or RAG tasks that already has a small eval set (for example 30-50 extraction or tool-calling cases). Run it against the same model at two precisions, such as a hosted BF16/FP8 endpoint and a local 4-bit quant, or a vendor QAD checkpoint vs a community PTQ GGUF. Score more than final-answer accuracy: also count malformed tool calls/JSON, instruction violations and retrieval misses at long context, since those are the failures that quantization shows first. If he trains anything himself, distil from the original model with a KL loss on his own task inputs. Don't fine-tune on labels.

## Episode
- Title: When the Answer Key Is Wrong, and How to Shrink a Model Safely
- Summary: An AI agent got 49 of 50 unseen physics problems right, partly by proving the experts wrong. Copilot puts local models behind an OS sandbox, Meta releases an 816B open model, Anthropic's leaked Q3 numbers show compute economics, and LLMs lean one way on contested economic effects. The deep dive covers why quantization-aware distillation keeps 2- and 4-bit models usable for agents where retraining breaks them.

GEORGE: So here's the framing. Until now you had two dials for spending compute. Make the model bigger, or let it write a longer chain of thought. Looping adds a third dial. You run the same layers several times for every token, and that extra thinking happens inside the hidden state instead of showing up as text.
MIA: Which immediately sets off my monitoring alarm. But let's earn that. Start with the mechanism.
GEORGE: Right. A normal transformer is a stack of layers, each with its own weights. A token goes in at the bottom, gets refined layer by layer, and a prediction comes out the top. If you want more capability, you add layers, which means more weights and more memory. A looped model stores a block of layers once and sends each token's hidden state through that block several times.
MIA: So depth without parameters.
GEORGE: Depth without stored parameters, yes. The usual shape is a sandwich. An input block runs once and translates tokens into the model's internal representation. Then a shared recurrent block in the middle runs k times. Then an output block runs once and turns the final state back into token predictions.
MIA: Give me the actual layouts, because I think the two models are quite different designs.
GEORGE: They are. Inkling 2 Mini has twenty-four layers in four blocks of six. Block one, the prelude, and block four run once. Blocks two and three run three times. So twenty-four stored layers become forty-eight layer applications per token.
MIA: And it's a mixture of experts on top of that.
GEORGE: Yes, so it's a bit of a layer cake. Twenty-six point four billion parameters in total, three point four billion active, and once you count the loop it's about five point four billion weight activations per token. Each token goes to eight of a hundred and twenty-eight experts per layer, and attention is a hybrid of local and global layers.
MIA: And Dory?
GEORGE: Much smaller and much deeper. Seventy-two physical layers: a sixteen-layer input block, a forty-layer shared recurrent block, and a sixteen-layer output block. So the effective depth is thirty-two plus forty times the number of loops. One loop, seventy-two layers. Four loops, a hundred and ninety-two.
MIA: A hundred and ninety-two layers deep on a four billion parameter model. That's a strange-looking animal.
GEORGE: It is, but the idea isn't new. It goes back to Universal Transformers, Dehghani and colleagues in twenty nineteen, and the key recent step was Ouro, from ByteDance Seed and others in twenty twenty-five. Those were research models. What's new now is that these two are post-trained, agent-capable, and you can pull them today.
MIA: My mental picture, tell me if it's wrong: it's like rereading the same paragraph three times. No new information, but you understand it a bit better each pass.

MIA: Here's my builder question though. If it's that simple, why didn't everyone do this years ago?
GEORGE: Because naively looping a network is unstable. Ouro trained with four recurrent steps. When they tried eight, they got loss spikes and went back to four. You're feeding a network its own output over and over, and small deviations can build up, a bit like a microphone held too close to its speaker.
MIA: Feedback.
GEORGE: Exactly. And the two new models fix it in different ways. Inkling 2 Mini does something I find quite elegant. Every pass restarts from the prelude output, so the middle block always sees the original input. Passes two and three additionally receive a "message" from the previous pass, merged in through a learned gate. And that gate starts fully closed.
MIA: So early in training each loop is basically an ordinary non-looped model.
GEORGE: Right. It behaves like a normal network, and the gate opens as training finds it useful to pass information forward. You don't start in the unstable regime, you grow into it.
MIA: And NVIDIA?
GEORGE: Dory re-injects the input block's output before every loop, so again the recurrent block never drifts too far from the original input. And it's built on a normalised transformer backbone, with L2 normalisation keeping the hidden states on a fixed scale, so the representation can't blow up as it goes round.
